# Watch Party Sync · 一起看视频同步工具

一个安静、低打扰的远程「一起看」工具，内置 bilibili 以及稀饭动漫、次元城、agefans 类等中小视频站点，其他站点可以在 Tampermonkey 菜单里一键匹配当前域名。它让两个或多个朋友能看到彼此的播放进度，并可选择跟随房主同步。

> 🐣 **只想装上用，不想看技术文档？**
> → 请看 **[新手安装教程（零基础，10 分钟）](docs/安装教程.md)**
> 本文档下面部分是给开发者/想自己搭后端的人看的。

这是规格文档
[`docs/superpowers/specs/2026-06-30-watch-party-design.zh-CN.md`](docs/superpowers/specs/2026-06-30-watch-party-design.zh-CN.md)
所描述的 MVP 版本：一个 **Tampermonkey（油猴）脚本** 作为前端，搭配一个小型的
**Cloudflare Worker + D1** 服务作为后端，采用 HTTP 轮询（暂不使用 WebSocket）。轮询间隔是自适应的：跟随中的参与者用 1.5 秒，其他人 5~10 秒。

## 它能做什么

- **看到彼此进度**：房间内每个人的当前播放时间、播放/暂停状态、在线情况都会显示。
- **可选跟随房主**：
  - 自动跟随房主进度：当本地与房主时间差超过 2 秒时，自动跳转到房主位置。房主的位置会按上报时间戳外推到「此刻」，所以轮询带来的延迟不会变成永久偏移。
  - 跟随房主播放/暂停：房主暂停或播放时，本地同步执行。
- **安静不打扰**：默认只在页面右侧显示一个半透明小圆钮，全屏播放时自动隐藏所有界面。
- **手动拖动保护**：你自己拖动进度条后，会有 8 秒不被自动拉回的保护窗口。
- **零账号**：不需要注册登录，凭随机房间码加入即可。

## 项目结构

| 路径 | 说明 |
| --- | --- |
| `userscript/watch-party.user.js` | 油猴脚本（前端，所有模块打包在一个文件里）。 |
| `worker/src/index.js` | Cloudflare Worker 入口：HTTP 路由 + CORS。 |
| `worker/src/room-service.js` | 房间/参与者核心逻辑（创建、加入、状态上报与拉取）。 |
| `worker/schema.sql` | D1 数据库表结构（`rooms` 和 `participants`）。 |
| `worker/wrangler.toml.example` | 复制为 `wrangler.toml` 并填入 D1 数据库 id。 |
| `tests/` | 基于 `node:test` 的后端测试（含内存版 D1 桩）。 |
| `fixtures/` | 本地适配器测试用的 HTML 页面。 |
| `site/` | 安装页（纯静态 Worker）。页面由 `docs/安装教程.md` 自动生成，并把脚本本体一起发布。 |
| `docs/` | 设计规格文档与本说明。 |

## 整体架构

```
┌─────────────────────┐      HTTP 轮询(自适应 1.5~10 秒)   ┌──────────────────────┐
│  浏览器 A (房主)     │  ── POST /rooms/:id/state ──▶    │                      │
│  油猴脚本           │  ◀── GET  /rooms/:id/state ──    │  Cloudflare Worker   │
└─────────────────────┘                                  │  + D1 数据库         │
┌─────────────────────┐                                  │  (rooms /            │
│  浏览器 B (参与者)   │  ── POST /rooms/:id/state ──▶    │   participants)      │
│  油猴脚本           │  ◀── GET  /rooms/:id/state ──    │                      │
└─────────────────────┘                                  └──────────────────────┘
```

- 前端检测当前视频，把本地播放状态上报给 Worker，并定时拉取房间状态、可选地跟随房主。
- 后端把房间与参与者状态存进 D1，职责非常轻：建房、加入、接收状态、返回状态。

## 第一步：申请并配置 Cloudflare D1

### 1.1 注册 Cloudflare 账号

1. 打开 [https://dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) 注册一个免费账号。
2. 免费套餐（Workers Free Plan）即可满足本工具的用量，无需绑定信用卡也能使用 Workers 与 D1 的免费额度。

### 1.2 安装 Wrangler 命令行工具

Wrangler 是 Cloudflare 官方的部署工具，需要本地已安装 [Node.js](https://nodejs.org/)（建议 18 及以上）。

```bash
npm install -g wrangler
```

安装后登录（会打开浏览器授权）：

```bash
wrangler login
```

验证是否登录成功：

```bash
wrangler whoami
```

### 1.3 创建 D1 数据库

进入 `worker` 目录，先把配置模板复制成正式配置：

```bash
cd worker
cp wrangler.toml.example wrangler.toml
```

创建 D1 数据库：

```bash
wrangler d1 create watch_party
```

命令成功后会输出一段类似下面的内容，**请复制其中的 `database_id`**：

```toml
[[d1_databases]]
binding = "DB"
database_name = "watch_party"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

打开刚才复制出来的 `worker/wrangler.toml`，把里面的占位 id 替换成上面真实的 `database_id`：

```toml
name = "watch-party"
main = "src/index.js"
compatibility_date = "2026-06-30"

[[d1_databases]]
binding = "DB"
database_name = "watch_party"
database_id = "把这里替换成你的真实 database_id"
```

> 也可以在 Cloudflare 控制台用图形界面创建：左侧菜单 **Storage & Databases → D1 → Create database**，名称填 `watch_party`，创建后在数据库详情页能看到它的 `database_id`。

### 1.4 初始化数据库表结构

把 `schema.sql` 应用到数据库。本地开发库和线上库要分别执行：

```bash
# 本地库（给 wrangler dev 用）
wrangler d1 execute watch_party --local --file=./schema.sql

# 线上库（部署到生产环境用）
wrangler d1 execute watch_party --remote --file=./schema.sql
```

这会建立 `rooms` 和 `participants` 两张表以及相关索引。

## 第二步：部署后端 Worker 服务

### 2.1 本地试跑（推荐先做一遍）

仍在 `worker` 目录下：

```bash
wrangler dev
```

成功后 Worker 会运行在 `http://127.0.0.1:8787`。可以用 curl 验证建房接口：

```bash
curl -X POST http://127.0.0.1:8787/rooms \
  -H "Content-Type: application/json" \
  -d '{"displayName":"Alice"}'
```

若返回类似 `{"roomId":"AB12CD","participantId":"p_...","hostToken":"h_...","role":"host"}`，说明后端工作正常。

### 2.2 部署到线上

```bash
wrangler deploy
```

部署成功后会输出线上访问地址，形如：

```
https://watch-party.<你的账号>.workers.dev
```

**记下这个地址**，第三步配置前端时要用到。

## 第三步：安装并配置前端油猴脚本

### 3.1 安装 Tampermonkey

在浏览器中安装 [Tampermonkey（油猴）扩展](https://www.tampermonkey.net/)（Chrome / Edge / Firefox 均支持）。

### 3.2 添加脚本

**最省事的方式**：打开你部署好的安装页（见[部署安装页](#部署安装页可选)，`site/` 会同时发布脚本本体），点 **「一键安装脚本」** 就装好了。没有反应就点「复制脚本代码」，再手动粘贴。

手动方式：
1. 点击浏览器工具栏的 Tampermonkey 图标 → **添加新脚本**。
2. 删除默认模板，把 `userscript/watch-party.user.js` 的全部内容粘贴进去。
   > 注意：仓库里的这份脚本用的是**占位地址**，需要按 [3.3](#33-配置-worker-地址关键) 换成你自己的后端；从安装页装的则已经替换好了。

### 3.3 配置 Worker 地址（关键）

在脚本顶部找到 `CONFIG` 配置块，修改这几项：

```js
const CONFIG = {
  // 本地开发用的 Worker 地址
  workerUrlLocal: "http://127.0.0.1:8787",
  // 你在第二步部署后得到的线上地址
  workerUrlRemote: "https://watch-party.example.workers.dev",
  // 日常使用填 false（走线上）；本地调试填 true（走本地）
  useLocalWorker: false,
  // ...
};
```

把 `workerUrlRemote` 改成你自己的 `workers.dev` 地址即可。

### 3.4 保存并启用

按 `Ctrl/Cmd + S` 保存。脚本以 `@match *://*/*` 安装，会注入到所有网站，但**只在你匹配过的域名上工作**：未匹配的域名完全无痕（不建 DOM、不发请求、不显示任何 UI）。

> 新增一个站点：打开那个网站，点 **Tampermonkey 图标 → 「匹配当前域名」**，面板立刻弹出，以后打开该域名自动生效——不用改脚本、不用重新安装。内置站点（bilibili、稀饭动漫、次元城、agedm、agefans）默认可用；要取消某个站点的匹配，用菜单里的「取消匹配当前域名」。

## 第四步：开始使用

> 第一次在某个网站使用：先点 **Tampermonkey 图标 → 「匹配当前域名」**。未匹配的域名上脚本完全静默——不显示面板，也不做任何事。

1. 默认情况下页面上**不显示任何悬浮窗或图标**，保持干净。需要一起看时，点击浏览器工具栏的 **Tampermonkey 图标 → 菜单中的「Open Watch Party」** 呼出面板。
2. 填入你的昵称，点 **Create room（创建房间）**，你就是房主，会得到一个 6 位房间码。进房后右侧才会出现小圆钮（悬浮窗），离开房间后再次隐藏。
3. 把房间码发给朋友，朋友同样用 Tampermonkey 菜单呼出面板，点 **Join（加入）**、输入房间码即可作为参与者加入。
4. 两个跟随开关**默认已开启**（面板里可以关）：
   - **自动跟随房主进度**：漂移 > 2 秒时跳转。房主的位置会用服务端时间戳外推到"此刻"，所以轮询延迟不会变成永久偏移。
   - **跟随房主播放/暂停**：房主按下播放时，成员会**先对齐到房主此刻的位置再开始播**；房主暂停时也会对齐到房主停下的位置。
5. **成员拖动进度条 = 向房主发一次请求**，不会直接改全房间：
   - 拖动后你自己的进度保持 **10 秒**不被拉回；
   - 同时房主面板会弹出气泡「**小林 想跳到 12:34**」，房主点〔跟随 TA〕全房间一起跳过去，点〔忽略〕则什么也不发生（那位成员 10 秒后自动回到房主进度）；
     - **只有你俩在看同一个视频时才会打扰房主**：跨视频拖动不会发请求（两边时间轴无关），房主侧也会过滤掉这类请求
   - 房主可以勾选「**自动接受成员拖动**」，信任的房间里就不用每次点气泡。
6. **谁卡住，全房间一起等**：任何人的画面在缓冲（没有暂停、但进度不动），其他人的面板会显示「等待 XX 缓冲…」并自动暂停；对方恢复后自动继续播，并先对齐位置（不会产生偏移）。房主面板上会多一个〔**不等了，继续播放**〕按钮，不想等就直接点，这一轮卡顿里大家都继续播。
7. 同一浏览器同一房间**只有一个标签在「同步中」**，而且**同步权永远不会被自动抢走**：打开新标签、刷新、后台标签被浏览器降频——都不会让它偷偷开始同步。想换标签就在那个标签的面板里点〔**同步当前视频**〕，它会立刻接管，原标签自动停手。
   > 这条靠 Tampermonkey 的共享存储实现，所以**不同站点的标签页之间也能协调**（比如 bilibili 一个标签、稀饭动漫一个标签）——实测确认有效 ✓。
   > 设计上刻意不用「心跳 + 超时」去猜哪个标签还活着：Chrome 会把后台标签的定时器压到大约每分钟一次、甚至冻结，这种猜法必然误判（旧版本就是这样出现多个标签同时上报、进度来回跳的）。现在是**用户点谁就是谁**，另外用 `sessionStorage` 记住"是本标签"，所以 **F5 刷新后继续保持同步**，而新开的标签拿不到这个身份、只能等你去点 ✓。
   > 没在同步的标签也会每 5 秒拉一次房间状态（只看不发），所以它的面板照样有成员列表，也能第一时间显示「不同视频 + 跳转按钮」 ✓。
8. 如果当前页面和房主不是同一个视频，会暂停跟随，并在面板显示「跳转到一起看的视频」按钮——点它会暂停当前视频并在新标签打开房主的视频；**这个新标签会直接接管同步**，旧标签自动停手（这是一次性交接：只有落在那个 URL 上的标签才会接管，普通新标签不会）。
   - 如果目标站点**还没匹配过**，点跳转时会**自动帮你匹配**它（否则新页面里脚本根本不运行、也就没法同步），提示会写明「已在新标签打开，并自动匹配了该站点」
   - 万一新页面没能接管（比如目标页面加载失败、或脚本没在那里运行），**不会有任何自动接管**：回到旧标签点〔同步当前视频〕即可 ✓
   **跨站点看同一个视频**：如果同一部番你在另一个站点看（页面地址不同 → 脚本判定为"不同视频"），这时点横条/气泡里的〔**强制同步**〕，就会**照样按房主的时间轴跟随**（进度 + 播放/暂停 + 漂移纠正）。
   - 打开后横条变成状态行「已强制同步：你和房主不在同一页面，进度仍会跟随。」，再点〔取消强制同步〕关掉；**离开房间会自动关掉**
   - 房主面板里那一行会显示「**强制同步**」（而不是"不在同一视频"），而且你拖进度条发出的**跳转请求依然有效**
   - 注意：两个站点的片源如果本身时间轴对不齐（比如片头长度不同），会反复纠正位置——那种情况更适合用〔跳转到一起看的视频〕
9. 同步中的标签切到后台再切回前台时，会立即对齐到房主进度（漂移不大则不跳动）。
10. 轮询是自适应的：**只有"会被拽动"的标签才走 1.5 秒一次**——也就是正在跟随房主的成员，外加「不同视频判定还没落定」的那个短暂窗口。房主自己不跟随、不同视频的成员也不跟随，都走 5 秒；房间里只剩自己时 10 秒。没在同步的被动标签也是 5 秒（只看不发）。
11. 面板约 10 秒无操作后自动收起（除非选了 **Pinned 固定** 模式）。**默认显示方式是「状态条」**，可以在面板底部改。
12. **提示气泡**：面板收起（或全屏）时，重要提示会以气泡形式出现在右下角（全屏时在右上），例如「等待 XX 缓冲…」「小林 想跳到 12:34」「你和大家不在同一个视频」。气泡上直接带按钮——跟随 TA / 忽略 / 不等了，继续播放 / 跳转到一起看的视频——点一下立即生效。
    - **所有提示都是气泡**（原来的"面板底部提示行"已经去掉）：面板收起时显示在右下角，**面板展开时显示在面板上方**；气泡宽度跟着文字走（短文本就窄，最长 304px）；按钮**每行一个**；气泡与状态条会**叠着显示**，互不遮挡
    - 气泡统一显示几秒后自动消失
    - **带按钮的气泡在面板展开时不出现**：那些按钮（跟随 TA / 忽略 / 不等了 / 强制同步…）面板里本来就有对应的横条，气泡再来一份纯属重复、还会挡住面板。纯文字提示（例如「连不上同步服务」）没有对应物，所以面板展开时照常显示。
    > 全屏时的限制：浏览器只渲染「全屏元素及其子树」。所以脚本会把自己的 UI **搬进全屏元素**；如果站点是把 `<video>` 本身（或 iframe）全屏，浏览器不允许任何叠加层，气泡也看不到——这是浏览器限制，不是脚本能绕过的。
13. 房主自己拖动进度条时会看到「已更新进度，成员将会同步」；成员那边会看到「房主调整了进度」，知道自己为什么被跳转。
14. 点 **Leave（离开）**（或菜单里的「Leave room」）会移除全部界面，页面恢复到原始干净状态。

## 部署安装页（可选）

`site/` 是一个**纯静态 Worker**，把安装教程做成网页，并顺带发布脚本本体，于是：

- 打开网页就能看教程，点 **「一键安装脚本」** 直接进 Tampermonkey 安装流程
- 点 **「复制脚本代码」** 一键复制全文（可手动粘贴到油猴）
- 点 **「复制安装地址」** 把 `.../watch-party.user.js` 发给朋友，他点开就能装

页面内容由 `docs/安装教程.md` **自动生成**，所以文档改了网页就跟着变，不会出现两份内容对不上。

```bash
cp site/wrangler.toml.example site/wrangler.toml   # 填你自己的域名
cp site/config.example.json site/config.json       # 填你自己的后端主机名
npm run site:build     # 生成 site/public/（该目录不入库）
npm run site:deploy    # 生成 + 部署
```

`site/wrangler.toml`（**不入库**，只在你本地）里的 `routes` 决定域名。**注意 TOML 语法：顶层键必须写在任何 `[table]` 之前**，否则 `routes` 会被当成 `[assets]` 的字段而静默失效（只部署到 `*.workers.dev`，不绑域名）。

`site/config.json`（同样**不入库**）里的 `apiHost` 会在构建时注入到发布出去的脚本里 —— 所以仓库里只有占位地址，别人 clone 下来也拿不到你的部署信息。

静态资源的请求是**免费且不计入** Worker 请求配额（它们不会真正执行 Worker 脚本），所以这个站点不会挤占同步服务的每日额度。

## API 接口说明

所有响应均为 JSON，Worker 会带上允许跨域的 CORS 头。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /rooms` | 创建房间。返回 `roomId`、`participantId`、`hostToken`。 |
| `POST /rooms/:roomId/join` | 加入房间。返回 `roomId`、`participantId`、`role`。 |
| `POST /rooms/:roomId/state` | 上报本地播放状态。房主需带上 `hostToken`。 |
| `GET /rooms/:roomId/state` | 拉取房间内所有参与者的状态。 |

错误码：`400` 负载非法，`403` 房主 token 无效，`404` 房间不存在。

### 请求频率与免费额度

脚本按角色自适应节流，而且**只有被明确选中的那个标签会请求**（其余标签是被动查看，只拉取、绝不上报）：

| 场景 | 上报心跳 | 拉取轮询 | 合计/天·人 |
| --- | --- | --- | --- |
| 同步中的标签，一个人在房间里挂机 | 30s | 10s | ≈ 11,500 |
| 同步中的标签，在房间里但没在跟随（房主 / 不同视频 / 关了自动跟随） | 5s | 5s | ≈ 34,600 |
| 同步中的标签，正在跟随房主（真正在一起看） | 5s | 1.5s | ≈ 74,900 |
| 没被选中的被动标签 | —（不上报） | 5s | ≈ 17,300 |

播放/暂停/拖动等**事件发生时会立刻上报**，上表只是心跳的下限，所以放慢心跳不影响响应。

Cloudflare 免费额度是 **100,000 请求/天**（每天 08:00 北京时间重置）。所以：

- 挂机一整天、或者一起看几个小时 —— 完全够用；
- **两个人一天 24 小时不间断跟随**（≈150,000）会超，需要升级 Workers 付费（$5/月，含 1000 万请求）或别一直挂着。

隐藏标签页会被浏览器降频，实际用量通常明显低于上表。

**上报状态请求示例：**

```json
{
  "participantId": "p_...",
  "hostToken": "h_...",
  "state": {
    "currentTime": 123.4,
    "duration": 1440,
    "paused": false,
    "url": "https://example.com/video",
    "title": "第 1 集",
    "source": "video-src-or-page-id",
    "adapter": "generic-video"
  }
}
```

`currentTime` 可以是 `null`，意思是"**客户端此刻报不出位置**"（换集、播放器刚重建、`<video>` 还没加载好）。
这种情况下 Worker 会**保留上一次的有效位置**，而不是把它当成 0 —— 否则整房间会被拽回片头；
如果该参与者从来没有报过位置，字段就保持缺失，面板显示 `—` 而不是 `0:00`。

## 适配器说明

前端采用分层适配器策略，所有适配器暴露相同接口（`detect`、`getState`、`seek`、`play`、`pause`、`onChange`）：

- **通用页面视频适配器**：自动挑选页面里最可能是「主视频」的 `<video>`（可见、有时长、渲染面积最大；忽略广告/预览类小视频）。
- **iframe 聚合适配器（顶层窗口）**：监听各 iframe 上报的视频状态，并能向下广播 seek/play/pause 控制指令。
- **iframe 上报器（运行在 iframe 内）**：检测内嵌 `<video>` 并把状态 `postMessage` 给顶层窗口，同时执行顶层下发的控制指令。
- **bilibili 适配器**：优先选取主播放器容器内的视频，避免触碰弹幕、登录、画质等控件。

agefans 类站点通过 iframe 路径工作，思路与 "Agefans Enhance" 一致——把内层帧的播放事件转发给外层页面。

若页面找不到可控视频，面板会显示「**player not detected（未检测到播放器）**」而不是静默失败。

## 安全与隐私

- 油猴脚本只上报同步所需的播放元数据：房间 id、参与者 id、昵称、当前时间、时长、暂停状态、页面 URL、页面/视频标题、来源标识、适配器名。
- **不会** 收集 cookie、账号 token、弹幕数据或页面 HTML。
- 房主 token 仅存在本地，绝不在界面上显示。
- 房间码是随机生成的，难以被随意猜中。
- 当前 Worker 的 CORS 设置为 `Access-Control-Allow-Origin: *`（符合 MVP 设定：无账号、无凭证，只流转不透明的房间码/token）。若后续加入敏感内容，建议收紧为指定来源。

## 常见问题

**Q：`wrangler d1 execute` 报找不到数据库？**
A：确认 `wrangler.toml` 里的 `database_name` 与 `database_id` 已正确填写，且和 `wrangler d1 create` 时使用的名字一致。

**Q：脚本装好了但右侧没有出现小圆钮？**
A：小圆钮只在已匹配的域名、且进入房间后才出现。未匹配的域名上脚本完全静默，点 **Tampermonkey 图标 → 「匹配当前域名」** 即可启用；内置站点（bilibili、agedm、agefans 等）默认已匹配。另外，没进房间时页面上本来就没有圆钮，需要从菜单「打开一起看」呼出面板。

**Q：能创建/加入房间，但进度不同步？**
A：确认参与者已勾选「Auto-follow host progress」；同时注意只有房主的进度会被其他人跟随，并且漂移要超过 2 秒才会触发跳转。房主刚按下播放的那几秒里，成员会先对齐到房主当前位置再开始播放，所以不会出现"永远慢几秒"的累积偏移。如果偏差很大，检查后端是否已部署带 `serverTime` 的版本（没有它会退化成不对齐外推，但仍会追平）。

**Q：面板提示 Sync unavailable / Host offline？**
A：`Sync unavailable` 表示连不上 Worker，检查 `workerUrlRemote` 是否正确、Worker 是否已部署；`Host offline` 表示房主长时间没有上报状态。

**Q：以后想换成 Chrome 扩展？**
A：脚本已按 `apiClient`、`roomStore`、`videoAdapters`、`syncEngine`、`panelUi`、`settings` 模块化组织，后端 API 与同步规则可直接复用，只需把 Tampermonkey 的存储/菜单 API 换成 Chrome 的 storage、popup、content script 即可。
